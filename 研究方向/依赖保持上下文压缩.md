# 任务导向的分级保留与依赖组预算分配

## 一、研究问题与目标

本课题研究：**在有限 Token 预算下，怎样保留生成有效测试所需的代码细节与依赖关系，同时压缩重复和次要信息。** 研究对象是提供给大模型的上下文，生成模型保持固定；测试仍在原项目中执行。

从视觉 Token 压缩迁移重要信息保留细节、背景信息紧凑表达的思想，形成面向代码的分级压缩方法。[1,2] 方法重点不是单纯删短输入，而是让保留下来的信息能够共同支持对象构造、状态准备、目标调用和预期结果检查。

### 1.1 固定研究范围

| **内容** | **本任务安排** |
| --- | --- |
| 主任务 | Python 单元测试补全；优先采用 TestGenEval 的 extra test completion 设置。[4] |
| 输入与输出 | 输入为基准允许的被测代码、已有测试、任务指令与预算；输出为带来源标记的压缩文本，再交给固定模型生成测试。 |
| 资源与协作 | 以单张 RTX 4090（24GB）为主力。新 A 独立研究上下文压缩；B 继续研究补丁正确性评估，互不依赖。 |

### 1.2 一个贯穿方法的例子

为 read() 补充测试时，代码可能分别在构造函数中设置 initialized=False，在 open() 中准备资源并更新状态，在 read() 中检查状态并读取。只保留 read() 的关键词相似片段，可能遗漏合法调用所需的准备条件。

任务把状态定义—状态更新—条件检查—目标操作作为一组候选依赖信息。关键条件原样保留，背景实现适度缩写，预算优先用于能够组成有效行为依据的信息组合。

## 二、思想迁移与方法定位

### 2.1 从视觉方法迁移什么

| **方法思想** | **原工作的做法** | **本任务的具体迁移** |
| --- | --- | --- |
| 关键细节与背景分开处理 | VisionZip 选择主要视觉 Token，并将其余 Token 中的相似信息合并为上下文表示。[1] | 关键条件、参数和状态操作保留原文；次要函数保留接口或相关片段，重复测试仅保留代表片段和差异。 |
| 压缩与下游任务适配 | UniCompress 以轻量、模块化的压缩／解压设计适配统一视觉模型。[2] | 固定测试生成模型，只调整输入端压缩器；必要时学习小型信息评分器，不重训生成模型。 |
| 结构化的分层压缩 | LongCodeZip 先选函数，再选函数内部代码块，并分配 Token 预算。[3] | 继承函数／代码块粒度，进一步为同一单元选择保留精度，并联合选择相互依赖的单元。 |

**迁移发生在信息选择机制上。** 视觉特征可以做向量合并，源代码却包含不可随意混合的标识符、运算符和状态条件。本任务输出可阅读文本，采用原文摘取与结构化省略，不把代码向量平均后当成源代码。

### 2.2 本任务要做出的区别

LongCodeZip 已研究分层选择与预算分配；已有测试生成工作也强调依赖上下文。[3,7] 因此，本任务将改进集中在：**同一信息单元保留多少细节、多个单元怎样共同进入预算，以及这种组合是否真正改善测试结果。**

拟议方法把依赖组的完整程度与分级表示共同纳入预算选择。完整组中的成员不必全部保留完整实现：状态条件可能需要关键语句，而被调用对象只需接口和构造要求。这样减少“单段相关，但组合后缺少前提”的上下文。

### 2.3 首版方法及可发展的贡献

首版采用语法划分 → 分级表示 → 依赖组构造 → 预算内联合选择 → 固定模型生成测试。评分先由冻结代码编码器的相似度与少量结构特征构成，可以直接实现。

论文贡献围绕两项结果形成：一是分级依赖选择能否在相同预算内提升有效测试生成；二是能否以更少输入和更低总成本维持测试质量。方法可以免训练，也可以加入轻量学习；不把模型规模或训练轮数当作创新本身。

## 三、数据基础、任务设置与结果复用

### 3.1 直接使用现成基准

采用 TestGenEval：完整集合含 1,210 对代码与测试文件，来自 11 个 Python 仓库；Lite 版本含 160 对。[4] 起步从 Lite 中预先指定一批开发样本，用于环境联调、预算选择和错误分析，再在未用于调参的任务上进行正式比较。

主任务采用 extra test completion：输入被测源文件及当前已有测试，生成一个补充测试；原任务提供的测试可以进入上下文。[4] 保留基准的任务说明、测试插入方式和运行环境，只替换上下文组织方式。首版不额外读取全仓库文件，确保各方法面对同一信息池。

方法成熟后扩展到完整集合中的保留任务。若后续训练评分器，按仓库分组安排训练、开发和测试；同一文件及其不同预算版本始终同组。原基准是评测数据，不将它描述成已经提供了本研究专用训练集。

### 3.2 优先复用已有结果，关键缺口再补跑

| **已有材料** | **处理方式** |
| --- | --- |
| 可比设置的论文结果 | 数据版本、样本、生成模型与量化方式、原始信息池、预算口径、采样及评测方式一致时，可直接引用，明确标为“原文报告”。 |
| 公开的逐样本预测 | 先核对生成条件；相符时复用预测，在本研究共同样本与评价脚本下重新计分，避免重复生成。 |
| 同名数据集但设置不同 | 保留作文献参照；主比较只补跑必要方法，不把不同模型或不同子任务的数字混成同条件结果。 |

**数据集相同是复用的起点，不是唯一条件。** 压缩策略可以不同，其他影响比较的条件应对齐。只有总分而没有逐样本结果时，可以引用总分，但不能据此计算新的配对显著性检验。

LongCodeZip 原文评测代码补全、摘要与问答，并非 TestGenEval 的测试补全。[3] 因此，原文数据用于说明方法背景；在本任务上的主对照仍需适配运行。TestForge 的多轮测试生成结果也单列为流程参照，不直接与本课题单轮设置相减。[6]

执行顺序：先整理可复用材料清单，再决定补跑范围。数据、环境和代码能够复用的部分不重复建设；尚未取得的公开预测不预先写成“已复用”。

## 四、起步方法：分级表示与依赖联合选择

### 4.1 将代码与测试拆成结构完整的单元

使用 Python AST 划分函数、类、条件／循环代码块、字段定义和测试准备片段。记录源文件、位置、所属符号、定义与使用关系；先处理局部符号、显式 self 字段、直接调用和测试 fixture。无法解析的动态关系保留为未知，不猜测连边。

首版从任务指令、已有测试中的调用，以及被测文件的接口和分支提取任务相关线索。若任务明确给出目标函数，围绕它选择；若没有明确目标，不使用隐藏目标或参考测试来反推“应该看哪里”。

### 4.2 为单个信息单元提供四种表示

| **级别** | **保留内容** | **使用场景** |
| --- | --- | --- |
| 0 · 省略 | 不放入当前上下文。 | 与任务联系弱，或已经被其他信息覆盖。 |
| 1 · 接口 | 签名、已有类型信息、必要默认值；标明函数体省略。 | 需要知道如何调用或构造，但暂不需要内部逻辑。 |
| 2 · 相关片段 | 接口，加相关条件、状态赋值、返回或调用语句；保留所属控制结构和省略标记。 | 测试需要理解某种前提或行为，完整函数又过长。 |
| 3 · 完整实现 | 完整原文单元。 | 细节密集、函数较短，或片段化会丢失重要控制关系。 |

上述表示仅用于提示上下文，不替换项目文件。保留原文中的符号、常量和比较关系；接口来自声明，相关片段来自语法提取，不自动编造自然语言契约。生成的测试始终在未压缩的原项目中运行。

### 4.3 构造能够共同解释行为的依赖组

首版构造三类小组：状态定义／更新／检查；构造或 fixture／目标调用；输入条件／分支操作／返回或异常。每组先限制为 2–4 个信息单元，并为每个成员规定最低保留级别。组与组允许共享成员，Token 不重复计费。

例如，read() 的组可以要求：构造函数保留初始化语句，open() 保留状态更新和资源准备，read() 保留检查及读取操作。是否完整，依据这些具体片段是否还在，而不是只有相关函数名。这个完整只针对提取出的依赖组，不等同于证明全程序语义完整。

### 4.4 在预算内联合决定选哪些、保留多细

设信息单元 i 选择级别 xᵢ∈{0,1,2,3}，所得上下文为 C(x)。B 为完整输入预算，包含指令、位置标记、代码、已有测试及摘要文字；输出 Token 另行预留。所有成本使用生成模型的 tokenizer 计算。

```
x* = arg maxx F(x; q),     Tokens(C(x)) ≤ B
F(x; q) = ∑i ai(xi; q) + β ∑g wg Ig(x) − γ R(x)
```

aᵢ 为某级表示对任务 q 的单元效用；组完整性指标在依赖组 g 的全部成员达到规定最低级别时为 1，否则为 0；组权重表示该组的重要性；R 为重复信息惩罚。β、γ 在开发数据上确定。这里的 F 是拟议的信息选择评分，实际价值通过测试执行结果评价。

首版 aᵢ 使用冻结代码编码器的任务相似度，并加入目标关联、状态／分支角色、已有测试涉及情况等特征。重复项仅针对近重复片段和共同模板，不把同名变量或同类条件直接视为冗余。任务线索固定时缓存表示。

**搜索时同时考虑单个单元升级和整个依赖组升级。** 若只按单段增益逐个选择，必须合在一起才有用的成员可能始终排不进预算；组升级直接解决这个问题。

### 4.5 可以直接实现的选择过程

① 保留任务指令、输出要求、测试插入位置等固定部分；生成每个单元的候选表示，去掉没有信息或成本优势的重复选项。

② 建立候选动作：将一个单元提升一级，或将一个依赖组的成员一并提升到所需级别。已经保留的内容不重复计入动作成本。

③ 计算每个动作带来的 F 增量与新增 Token，按单位新增 Token 的增益选择可放入预算的动作；加入后重新计算相关动作的增益。

④ 预算用尽或没有正增益动作时停止。首版保留贪心结果；进一步改进时可用一次局部交换，检查换出低收益片段能否容纳更完整的依赖组。

⑤ 按文件、类与原文顺序输出，明确区分接口、相关片段和完整代码。最终重新分词检查总长度；若超出，撤销最低收益动作并重新检查受影响的组。

### 4.6 保留关键细节，压缩背景重复

已有测试中，共同准备代码保留一次；不同输入和预期结果分别保留。只有能够确认准备部分相同且差异已完整列出的重复片段，才合并为“公共准备＋差异列表”。做不到时保留代表原文或省略，不强行合并。

预算不足以容纳固定部分时，该预算对该样本不可行，统一报告；不静默删除必要信息。全上下文装得下时保留不压缩选项，不要求每个样本都达到同样的压缩倍数。

## 五、轻量学习与方法改进

### 5.1 先实现完整免训练方法，再决定是否学习评分

第一版直接实现分级表示、依赖组与预算搜索；预训练编码器保持冻结，用开发集确定少量评分权重。这已经是一个可评价的方法版本，不需要等大规模训练数据准备完成。

需要提高任务适配能力时，在训练任务上为每个任务生成 2–3 种同预算压缩方案，记录固定生成模型的运行结果。优先利用已经产生的对照日志；新增生成仅补足缺少的方案。测试集日志不用于学习。

构造偏好对：能够运行并通过、且带来覆盖增量的方案优于失败或无效方案；两者都有效时，以更高覆盖增量作为监督。相同结果或不稳定差异不强行配对。少量边界样本可重复生成核验，不用单次偶然成功当确定标签。

```
L = mean log(1 + exp(−[Fθ(x+; q) − Fθ(x−; q)]))
```

只学习 aᵢ 的小型评分头或少量结构权重；表示编码器与生成模型继续固定。训练直接评价已知方案，不需要对离散搜索反向传播，也不开展全模型强化学习。各任务的偏好对先在任务内部平均，避免长文件主导训练。

### 5.2 初版表现一般时，沿信息瓶颈改进

| **观察到的错误** | **优先改进** | **看什么结果** |
| --- | --- | --- |
| 测试对象构造失败、状态准备遗漏 | 改进 fixture、构造函数与状态更新的组匹配；优先补齐组，而非单纯加长输入。 | 合法运行比例、状态相关错误及相同预算下的覆盖增量。 |
| Token 减少，但关键分支仍覆盖不到 | 提高关键条件的表示级别；让条件、定义和实际使用一起保留。 | 分支覆盖增量和固定变异集合上的新增检出。 |
| 接口留下了，却误解具体行为 | 改进接口到相关片段的升级评分，保留必要参数、边界和返回逻辑。 | 错误类型变化；与统一保留精度比较。 |
| 保留很多相似测试，预算被占满 | 改进共同准备代码去重、代表测试选择和差异列表表达。 | 单位 Token 的新增覆盖；完整方法与去掉背景压缩的对照。 |

先选择一类错误深入，改评分、组构造或表示级别中的一项，保持其他条件一致。局部算法通过研究设计；研究对象、可用信息和正式测试划分的变化再与导师讨论。首版结果不是方向的能力上限。

## 六、实验设计与主要收益

### 6.1 三个研究问题

**RQ1：质量与效率。** 相同输入预算下，是否生成更多有效测试、提高新增覆盖？在测试质量相近时，能否显著减少输入 Token、总耗时和调用费用？

**RQ2：机制。** 分级表示、依赖组选择和背景压缩分别带来什么作用？收益是否集中在需要状态准备、多片段依赖及长测试上下文的任务？困难子集按输入属性事先定义。

**RQ3：迁移。** 保持压缩器不变，更换预算或固定生成模型，优势是否仍存在？学习版另外报告未见仓库结果。第二个生成模型放在后期，不作为首版启动条件。

### 6.2 先跑能解释方法价值的对照

| **对照** | **比较重点** |
| --- | --- |
| 完整上下文；同预算的普通截断 | 完整上下文是成本／质量参照，不预设其一定最优；超过模型上限时明确标注实际截断。 |
| 单元相似度排序；依赖检索＋统一精度 | 检验联合选择是否优于独立打分，分级表示是否优于只加入依赖。 |
| LongCodeZip；LLMLingua-2 | 分别作为代码压缩与通用压缩对照，优先使用公开实现和模型。[3,5] |
| 本方法去掉依赖组／统一精度／去掉背景压缩 | 保持原始信息池、生成模型、预算和生成次数一致；学习版另与免训练版比较。 |

### 6.3 指标、预算与公平比较

起步使用 4,096 与 8,192 两档完整输入预算；原始上下文已较短的样本单列。先固定每任务生成 1 次，主方法确定后在同一正式子集上使用 3 个生成种子；不把种子数当成新增独立任务。

保留基准原有运行指标；另报告新增行／分支覆盖、输入保留比例、压缩耗时、生成耗时和总成本。新增覆盖以同一已有测试集合为起点，在未压缩的源文件上计算；失败样本仍计入总体任务数，其新增覆盖记为 0。

后期对预先固定的代表子集运行变异测试，比较新测试额外识别了多少变异。各方法使用相同变异集合与超时规则，记录不可执行和未决变异；不把运行超时简单当作成功检出。测试执行与变异分析主要占用 CPU，也计入成本。

主表给出质量—预算曲线，而非只报压缩率。报告任务级配对差异与 95% 置信区间，跨仓库时按仓库分层或成组重采样。需要主张“质量基本保持”时，先在开发阶段定容忍幅度，再看区间，不用“不显著”代替等价。

### 7.3 现在就开始的工作

从 TestGenEval 的任务与运行说明、LongCodeZip 的方法和公开实现开始；先做同预算普通截断、相似度选择和本方法首版。不要等待全部文献读完，也不把所有基线全部复现完作为实现主方法的前置条件。

**推进原则：研究问题固定，方法可以改进；现成资产充分复用，关键对照按需补跑。** 有实质价值的质量或成本收益可以作为论文主结果，不要求每个指标同时领先。

## 八、核心阅读与参考文献（先读文献）

重点阅读 **[1]、[3]、[4]、[5] 四篇**。顺序建议为 [4] → [3] → [1] → [5]：先运行任务、理解直接竞品，再吸收视觉压缩与轻量评分思想。其余文献按对应问题查阅。

**[1] 视觉思想来源 · 重点读**

Yang, S., Chen, Y., Tian, Z., et al. VisionZip: Longer is Better but Not Necessary in Vision Language Models. CVPR 2025, 19792–19802.

阅读重点：重点看主要 Token 选择、上下文 Token 合并和免训练／轻量适配的区别。提炼信息保留原则，不复现视觉大模型训练。

[论文入口](https://arxiv.org/abs/2412.04467)

**[2] 模块化压缩 · 按需读**

Wang, Z., Chen, C., Li, J., et al. UniCompress: Token Compression for Unified Vision-Language Understanding and Generation. CVPR 2026. arXiv:2603.11320.

阅读重点：定向看压缩、解压和全局信息的组织方式；本任务不采用其视觉重建目标。

[论文入口](https://arxiv.org/abs/2603.11320)

**[3] 代码压缩直接竞品 · 重点读**

Shi, Y., Qian, Y., Zhang, H., Shen, B., and Gu, X. LongCodeZip: Compress Long Context for Code Language Models. ASE 2025. arXiv:2510.00446.

阅读重点：精读函数筛选、块级压缩和预算分配。用公开实现适配同一测试任务；分清哪些结果来自原文、哪些需要补跑。

[论文入口](https://arxiv.org/abs/2510.00446)

**[4] 数据与评价起点 · 重点读**

Jain, K., Synnaeve, G., and Rozière, B. TestGenEval: A Real World Unit Test Generation and Test Completion Benchmark. arXiv:2410.00752v2, 2025 revision.

阅读重点：先看 extra test completion 的输入、输出、测试插入与评价方式，再看 Lite、完整集合及覆盖／变异指标。

[论文入口](https://arxiv.org/abs/2410.00752)

**[5] 轻量压缩对照 · 重点读**

Pan, Z., Wu, Q., Jiang, H., et al. LLMLingua-2: Data Distillation for Efficient and Faithful Task-Agnostic Prompt Compression. Findings of ACL 2024, 963–981.

阅读重点：看 Token 分类、保留概率与小模型压缩。重点理解逐 Token 保留和本任务分级依赖选择的区别。

[论文入口](https://aclanthology.org/2024.findings-acl.57/)

**[6] 测试生成流程参照 · 按需读**

Jain, K., and Le Goues, C. TestForge: Feedback-Driven, Agentic Test Suite Generation. arXiv:2503.14713, 2025.

阅读重点：看执行反馈、覆盖与成本。多轮流程放扩展阶段，不直接用其分数证明单轮压缩方法优劣。

[论文入口](https://arxiv.org/abs/2503.14713)

**[7] 依赖上下文相关工作 · 按需读**

Context Matters: Improving the Practical Reliability of LLM-Based Unit Test Generation. arXiv:2607.19682, 2026.

阅读重点：定向看显式依赖、测试骨架与静态分析；写相关工作时明确本任务的分级压缩和联合预算设计。
