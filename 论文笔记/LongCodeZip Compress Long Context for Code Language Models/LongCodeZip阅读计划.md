# LongCodeZip 阅读计划

> Zotero 条目：`TTNLH8LX`；版本：arXiv:2510.00446v1，2025-10-01，13 页。作者：Yuling Shi、Yichun Qian、Hongyu Zhang、Beijun Shen、Xiaodong Gu。

## 研读目标

弄清 LongCodeZip 怎样在给定 Token 预算下，从长代码上下文中挑出对任务有用的函数和代码块；重点判断它的“依赖相关性”是否等同于研究方向所需的“依赖组共同保留”。

## 第一轮：问题与方法全貌（约 25 分钟）

**阅读**：摘要、引言、图 1–2、第 III-A 至 III-D 节（PDF 第 1–4 页）。

**带着这些问题读**：

- 输入由什么组成？压缩器得到任务指令、长代码上下文和预算；输出是什么形式？
- 为什么单纯按文本相似度检索会漏掉配置类等隐式依赖？
- AMI 用什么量来近似“片段对任务的帮助”？它和语义正确性有什么区别？
- 函数级筛选、函数内块级筛选各自解决什么问题？
- 自适应预算与 0/1 背包如何决定保留哪些块？

**可检查产出**：画出“指令＋代码 → 函数分块与排序 → 粗预算筛函数 → 困惑度边界分块 → 按函数分预算 → 背包选块 → 下游模型”的流程图；标注每一步使用的评分和预算。

## 第二轮：数据、指标与实验条件（约 30 分钟）

**阅读**：第 IV 节、表 I–VI（PDF 第 5–7 页）。

**带着这些问题读**：

- 三个任务各有多少样本、平均上下文多长？长上下文筛选阈值是什么？
- 压缩率的分子、分母各是什么？数值越大意味着什么？
- 代码补全的 EM 和 ES 分别衡量什么；摘要的 CompScore 如何消除评审顺序影响；RepoQA 的成功条件是什么？
- 下游生成模型和压缩模型是否相同？预算如何按任务设定？
- 结果是否和未压缩输入、同预算的压缩基线分别比较？表格数字对应哪个模型和数据集？

**可检查产出**：制作一张“任务—样本—输入长度—预算—指标—成功条件”表；选 Long Code Completion 的 Qwen2.5-Coder-7B 结果，用一句话准确写出压缩率和性能。

## 第三轮：消融、效率与可信边界（约 25 分钟）

**阅读**：第 V-B 至 V-D、第 VI–VII 节、表 VII–IX 和图 3–4（PDF 第 8–10 页）。

**带着这些问题读**：

- 去掉条件困惑度排序、细粒度压缩、自适应预算或困惑度分块后，结果怎样变化？
- 2.58 秒压缩开销与生成耗时减少放在同一流程中看，端到端节省是否已由表格直接报告？
- 作者承认了哪些失败情形、评测风险和数据集／模型局限？
- 论文中的“依赖”是 AMI 对任务提示的条件相关，还是静态分析得到的定义—使用关系？

**可检查产出**：列出三条“证据支持的结论”和两条“原文未证明的主张”；写下对自己方法最直接的公平对照方案。

## 建议的阅读顺序

1. 摘要＋图 2，先建立算法全貌。
2. 第 III 节，逐步核对输入、评分、分块和预算算法。
3. 第 IV 节＋表 I、II、III、IV、V，理解实验口径并挑一组条件读数字。
4. 表 VII–IX＋第 VI–VII 节，检查模块贡献、效率和局限。
5. 最后回到引言贡献，区分作者主张与实验实际覆盖范围。

## 研读时特别记下

- 不把“AMI 高”直接等同于“代码依赖被保全”；AMI 是压缩模型对任务文本的条件困惑度变化。
- 不把压缩比当成性能指标。压缩比只表示原上下文 Token 数除以压缩后 Token 数，性能须看对应下游指标。
- 不把多次实验当成更多独立任务：作者报告对 10 次重复实验用 Wilcoxon signed-rank 检验（第 V-A 节）；另有单次推理耗时表。
- 论文任务是代码补全、模块摘要和代码问答，不是单元测试补全。迁移时要重新验证任务适配性。
