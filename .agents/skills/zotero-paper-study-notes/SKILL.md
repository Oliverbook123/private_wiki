# Zotero 论文研读笔记

为用户指定的**一篇论文**制作两份可继续修改的 Markdown 文件：阅读计划与阅读笔记。以 Zotero 中的实际论文为依据；不要只凭摘要、题目或既有笔记概括全文。

## 找到并核对论文

先使用可用的 `zotero:Zotero` 技能操作本地 Zotero：检查连接状态，按标题／作者检索，核对选中的条目及 PDF 附件，读取全文。仅在用户要求或确认来源时处理 Zotero 写入；本技能通常只读。如果条目重名且无法可靠区分，询问用户。若 Zotero 未收录或全文不可读，说明具体障碍并请求论文或指向正确条目；不要悄悄用网页上的另一版本替代。

全文索引可能漏掉公式、表格列或图中文字。涉及关键数值、图表和实验设置时，核对 PDF 对应页面；无法核实时明确标记。记录标题、作者、年份／版本及 Zotero 条目 key，避免把不同版本的结论混用。

## 写给这位读者

用户习惯从具体问题理解论文：**输入是什么、输出是什么、数据怎样准备、模型做什么、程序怎样评测、各指标具体怎么算、结果能和不能说明什么**。先用一句通俗概括建立全貌，再按论文自身结构解释。遇到抽象指标，用小例子和必要的算式说明分母、统计单位与成功条件；清楚区分“模型生成一次／多次”和“评测程序重复运行”，以及数据构建、模型推理、结果评价三个阶段。不要假定读者已熟悉单元测试、覆盖率或突变测试。

阅读计划应按研究目的安排优先级：每轮读哪些章节／图表、带着哪些问题读、完成什么可检查的小产出。笔记应覆盖研究问题、贡献、数据与任务、输入输出与评测流程、核心指标、主要结果、作者分析、局限，以及与用户当前研究方向的关系。先读当前研究方向文件（若用户提供或工作区已有），再做针对性取舍；不要把相关性推断写成论文已证明的结论。对于未做的实验或未报告的指标，直接说明缺口。

把论文事实、作者解释和自己的推断分开写。数字要标明对应的数据集、子任务、模型与实验条件；不同条件的分数不直接相减。章节、表格或图号应能帮助用户回到原文核查。不要为凑齐模板而编造某篇论文不存在的指标或实验。

## 保存与后续修订

在本知识库工作区，默认将两份文件放入 `论文笔记/<论文标题>/`，命名为 `<短标题>阅读计划.md` 与 `<短标题>阅读笔记.md`。先查看该目录的现有文件，避免覆盖用户修改。按照工作区 `AGENTS.md`，`论文笔记` 不属于知识库，不加入知识库索引，也不套用知识库规范。若用户指定其他位置或只要一种产物，按用户要求处理。

用户继续追问概念时，先直接回答；只有用户要求加入笔记、或发现现有笔记确有错误时，才修改文件。修订时保留用户已有内容与命名。完成后给出两份文件的绝对路径链接，并简述笔记的重点。
