# 论文笔记写作规范（paper-note）

为用户在读过的论文旁撰写阅读笔记。用户的使用习惯：**自己手写模板（笔记YYYYMMDD.md），AI 填成成稿（另存新文件）**。核心纪律：模仿而不越位。

## 工作流程

1. **定位目录**：笔记放在 `论文笔记/<论文完整标题>/` 目录下（目录名沿用用户建好的，内含双空格等也原样使用，不要"优化"）。
2. **找模板**：查找目录内已存在的 `笔记YYYYMMDD.md` 或其它用户手写稿。
   - 有 → **只读不改**。它是用户的实时手写模板；所有补写内容写进**新文件**（命名：`<论文名>笔记YYYYMMDD.md`，或用户指定的名字）。
   - 没有 → 可以新建，但结构仍按下方"笔记结构"从零搭出（提前问用户是否有偏好格式）。
3. **找图**：用户提供图片时（SVG/PNG），复制一份进目录下的 `img/` 子文件夹，笔记用相对路径 `img/xxx.svg` 引用；禁止用绝对路径。
4. **对原文取证（关键）**：写笔记前，用 Zotero 工具搜论文原条目（zotero_search → zotero_retrieve 分主题取证）。本库 Zotero 只读不可写。每篇成果要核对：
   - 实验数字（加速比、精度、参数量）→ 逐个对原文
   - 理论结论（复杂度、定理条件）→ 对到具体定理/命题编号
   - 原文给不出的数字 → 在笔记中标注"流传口径/整理口径"，不冒充原文
5. **写入后自查**：所有 markdown 表格**前后必须留空行**（Obsidian 才渲染）；通读检查坏句/乱码字符；数字前后一致。

## 笔记结构（用户模板的骨架）

```markdown
# 笔记YYYY/MM/DD

**论文：** <英文标题>（<作者> 等，<venue 年份>）

# 前言
<一两句论文背景>。但是面临几个问题

### 问题
1、<论文要解决的问题一>
2、<问题二（若有；近似/已有方案的缺陷）>

### 方案
提出提出xx算法：
1、（前向传播阶段）<技术一>：<用户模板的句式——"手段：作用方式">
2、（反向传播阶段）<技术二>：…
3、<技术三>：…
4、效果：<复杂度/速度/内存的一句话对比>

<流程图（若有）>

## 实验：
<先一句总说明：实验怎么组织、是否从头重训>
分别将<被试模型>进行重新训练和对比
### <被试模型 1>.
协议：<训练配方一行话>
结论：
1、<数字结论一>
2、…

### <被试模型 2>.
（同上格式）

### <按需增开的实验小节>（如基准套件、长上下文、微基准…）
…

## 总结
1、<方法本质一句话>
2、<和同类方法的差别一句话>
3、<后续影响/回看一句话>

## 疑问（待补）
1、<没看懂的/待核的>
```

## 风格铁律（从用户手稿提炼）

- **短句流水账**：一句一个事实；"因此/所以"直连因果，不用长从句
- **顿号编号**："1、"、"2、"，不用 1. 或 -
- **术语不空格**：transformer、QKV、online softmax 连写；中文里夹杂英文不加大空隙
- **几乎不加粗**：除非一节只强调一个词
- **数字结论化**：结论条目 = "数字 + 一句解释"，如 "20.0min → 17.4min，端到端快15%"
- **口径必标注**：非原文数字写"（流传口径）"，非论文给的写"（整理口径）"
- **直接式答案**：解释方法时用"输入什么→输出什么，就这一个/没有别的"句式，不"拆三层"、不"用大白话说"开场、不铺垫歧义拆解；示例（用户认可的表达）：
  - "输入客服和用户每一轮的聊天内容，输出一个成交概率，每聊一轮算一次。没有别的决策：不选话术、不选动作，就这一个数（再加个置信度）。"
- **成功句式示例**（源自用户）：
  - "自注意的时间和内存复杂度是序列长度的二次方，因此transformer在长序列上速度慢且内存消耗大。"
  - "（反向传播阶段）Recomputation重计算：避免反向传播过程中重新读取HBM，通过直接重新计算的方式（重算要比从HBM重新读取要快）"
  - "结论：\n1、20.0min → 17.4min，端到端快15%"

## 对话风格（回复用户的嘴）

聊天里回答论文问题时和笔记同一个腔调：
- **第一句就是答案**；先说"是什么"，别先讲背景
- 一句一个事实，短句直给；不层层铺垫、不"拆开看有三层"、不用批判腔挂尾巴
- 数字直接给，来源有争议才补一句口径
- 用户说"就这么说话"即认可，保持住

## 详版笔记（可选，用户要求时才做）

同名目录下的 `<论文名>阅读笔记.md`：完整章节（背景动机 / 方法 · 伪码 / 复杂度表 / 实验流程方法论 / 个人思考要点 / 疑问清单），末尾追加"原文核对记录"（日期、zotero ref、修正过的错误、已核对/待核标注）。

## 禁止事项

- **绝不覆盖/修改用户手写的模板文件**
- 不往知识库 SCHEMA 的 frontmatter 里插手（论文笔记不属 SCHEMA 管辖，用户已言明）
- 不用绝对路径引图；不带 frontmatter
- 不虚构数字；不确定的口径必须标明
- 目录名/文件名照用用户建好的，不"修正"空格拼写
